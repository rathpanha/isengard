# Isengard 0.1.11 (Linux + macOS)

macOS fixes. Tag, `Cargo.toml`, and package filenames all use **0.1.11**. Linux
is unchanged apart from the version.

## Fixes (macOS)

- **App crashed at launch** ("Isengard cannot be opened because of a problem")
  in the 0.1.10 macOS build: it linked Homebrew's `liblzma` dynamically. It is
  now built in statically, and packaging fails if any non-system library gets
  linked.
- **Claude Agent did not start** (`env: node: No such file or directory`) and
  the terminal could not find tools such as `oh-my-posh` when Isengard was opened
  from Finder or the Dock. Isengard now picks up your login shell's `PATH` (cached,
  so only the first launch waits for your shell), and the terminal starts a login
  shell like Terminal.app.

## Updating

**Check for Updates…** works as before. On macOS 0.1.10 cannot start, so
reinstall once:

```sh
curl -fsSL https://raw.githubusercontent.com/rathpanha/isengard/master/scripts/install-macos.sh | bash
```

## Not in this binary

- Language servers (install from the LSP status menu)
- Claude Agent adapter (install from the Agent panel; login is the agent’s)
- Windows installer (not shipping yet)

## Verify

```sh
shasum -a 256 -c SHA256SUMS
# optional, with minisign installed and minisign.pub from the repo:
minisign -Vm SHA256SUMS -p minisign.pub
```
