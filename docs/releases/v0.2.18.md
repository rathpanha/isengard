# Isengard 0.2.18 (Linux + macOS + Windows)

Tag, `Cargo.toml`, and package filenames all use **0.2.18**.

## Changes

- **Windows: fix in-app update.** Updating failed with `create …\vcruntime140.dll:
  The process cannot access the file because it is being used by another
  process (os error 32)`, because the running app has the CRT DLLs loaded. The
  updater now stages the whole zip, renames each existing file to `*.old`,
  swaps in the new ones, and puts everything back if a step fails. Leftover
  `*.old` files are removed at the next launch.

## Updating from Windows v0.2.17 or older

The old updater cannot apply this fix to itself. Reinstall once by hand; later
updates work in place:

```powershell
irm https://raw.githubusercontent.com/rathpanha/isengard/master/scripts/install-windows.ps1 | iex
```

## Updating

**Check for Updates…** updates Linux, macOS and Windows installs in place.

## Not in this binary

- Bun (downloaded on first launch)
- Language servers (install from the LSP status menu)
- Claude / Cursor Agent adapters (install from the Agent panel; login is the
  agent’s)

## Verify

```sh
shasum -a 256 -c SHA256SUMS
# optional, with minisign installed and minisign.pub from the repo:
minisign -Vm SHA256SUMS -p minisign.pub
```
